## 준비된 도구

`scripts/`에 3–7단계용 스크립트가 있다. 임시 폴더에서 실제 이미지 사본으로 시험했고, 실제 `DATA_v001`은 아직 만들지 않았다. 실행 명령은 [README.md](../README.md)에 있다.

## 범위

**팀원 1이 하는 일:** 원본 보존, 출처 기록, 작업본과 기초 검사, 상자 검토, 중복 1차 판정, 인계.

**팀원 1이 하지 않는 일:** `groups_reviewed.csv` 작성과 그룹 ID 승인, R/G 분할 생성, `READY_FOR_TRAINING` 표시. 라벨과 중복 판정의 `reviewer`에는 판정한 사람을 적고 AI를 적지 않는다.

### 3단계 검증

변환한 박스 7,126개를 픽셀 좌표로 되돌려 CSV와 대조한다. 원본은 수정하지 않는다. 변환은 합의 후에만 실행한다.

### 5단계 표본

분할, 접두, 박스 크기, 객체 수에 고르게 나눈다. 툴킷의 기본 오버레이 20장은 train의 접두 없음 10장과 valid의 `a` 접두 10장으로 치우치므로 그대로 쓰지 않는다.

특이 사례:

- 한 변이 5px 이하인 박스 26개와 1×1 박스(`c--81`)
- 테두리에 닿은 박스
- 353×336 이미지 4장
- 라벨 없이 보이는 입자. Kaggle 전처리에서 클래스 3개가 제거되었기 때문일 수 있다

### 6단계 판정 범위

- dHash 1,256쌍을 전수 검토하지 않는다. 팀원 2와 합의해 보강 신호 상위, 경계 사례, 무작위 표본을 고르고 검토·미검토 수를 남긴다.
- R/G는 전체를 다시 섞으므로 분할 간 쌍뿐 아니라 같은 분할 안의 쌍도 본다.
- 알고 있는 이미지를 반전, 회전, 크롭해 넣고 탐지되는 비율을 먼저 측정한다. 그래야 "중복 미발견"이 방법의 한계인지 실제 결과인지 구분할 수 있다.
- `d--31`/`d--32`처럼 재배치로 보이는 사례는 `uncertain`으로 넘긴다.
- dHash 후보를 연결해 묶지 않는다. 거리 5 이하를 연결하면 307장 묶음이 생긴다.

```
  review/label_review.csv

  review/image_meta.csv               추가: 이미지별 접두와 번호. 시료 정보가 아님
  review/image_coverage.csv           추가: 이미지별 탐색 방법과 사람 검토 여부. group_id 없음
  review/duplicate_search_notes.md    추가: 탐색 방법, 탐지 성능, 놓칠 수 있는 변형, dHash 연결 경고
  source_notes.md
  handoff.json
```

추가 파일은 `handoff.json`의 `files`에 적는다. 사용한 툴킷의 해시도 남긴다. 상태 값은 `READY_FOR_REVIEW` 또는 `REVIEW_NEEDED`만 쓴다.

사전 점검:

- 다른 경로로 복사해 audit를 다시 돌려도 결과가 같은가
- `handoff.json`의 파일이 실제로 모두 있는가
- `pair_review`와 `label_review`의 ID가 `images.csv`에 모두 있는가
- 판정 값이 허용된 값뿐인가
- `make_official`이 test 때문에 실패하는 것이 안건으로 기록되어 있는가

팀원 3에게 출처와 라벨 품질 설명 초안, 최종 변경 이력을 준다. 팀원 2의 확정 그룹과 라벨 수정·제외 결과를 확인해 데이터 설명을 갱신한다. 파일이 바뀌면 `DATA_v001`을 덮어쓰지 않고 `DATA_v002`를 만든다.
